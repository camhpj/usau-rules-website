# Best Perspective

A SvelteKit app for exploring the USA Ultimate rules of ultimate and quizzing yourself on them. It runs on Cloudflare Workers, with D1 for anything that persists.

`README.md` covers the stack, local setup, and how each feature works. Read it before changing an area you have not worked in yet.

## Writing

These apply to everything: chat replies, code comments, commit messages, PR bodies, and docs.

- Write plain language, in the sense of the [US Plain Language Act](https://digital.gov/guides/plain-language).
- Prefer short declarative sentences, one idea each. Vary the length. A short sentence after a long one gives the reader room to breathe.
- Give every fact one home. Cross-reference it elsewhere rather than restating it.
- Let detail track risk. Specify contracts, security boundaries, data invariants, and anything expensive to change later. For the rest, state the requirement and leave the approach open.
- State decisions without defending them inline.
- Never invent a metric, baseline, or fact. Say what is unknown.
- At most one em-dash per paragraph. If a sentence needs two, split it.
- Avoid slogans. If a sentence sounds quotable, rewrite it to sound ordinary.

Read `docs/writing-guidelines.md` before drafting a spec, plan, or PR body. It covers document structure and the failure modes that show up in longer drafts.

## Gotchas

- `content/rulesets/**` and `static/search/**` are generated by `npm run ingest` and committed. Fix `scripts/ingest/` and re-run it. Do not hand-edit the JSON.
- `content/questions/**` is a human-reviewed quiz bank. `npm run seed:questions` appends Gemini-drafted candidates to those files for review, and `--force` discards the existing questions in the sections it targets.
- `BETTER_AUTH_URL=` is empty in `.dev.vars` on purpose. It overrides the production value in `wrangler.jsonc` so local auth derives its origin from each request. Leave it empty.
- `ALLOW_TEST_SIGNIN=1` enables an email/password sign-in used by local dev and e2e. It must never be set in production.
- `npm run db:migrate:remote` applies migrations to the production D1 database. `db:migrate:local` targets the local Miniflare copy.
- Playwright needs a `.dev.vars` file to exist. CI creates one by copying `.dev.vars.example`.
- Code under `src/` runs on Cloudflare Workers, so Node built-ins are unavailable at runtime. Scripts under `scripts/` run under `tsx` in Node, where they are fine.

## Verifying

```bash
npm run check          # svelte-check
npm run test           # vitest
npx prettier --check . # formatting
```

`.github/workflows/ci.yml` is the full gate. It adds `check:scripts`, `check:e2e`, `validate:content`, `build`, and the Playwright suite.
